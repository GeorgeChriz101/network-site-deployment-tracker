# Project Methodology

## Step 1 - Define the Deployment Lifecycle

The project models five major phases of cellular site deployment:

1. Site Survey
2. Permitting
3. Equipment Delivery
4. Installation
5. Acceptance

Each of five sites follows this lifecycle.

## Step 2 - Build the Master Schedule

A schedule is created with:

- 5 sites
- 5 milestones per site
- 25 total milestones
- Planned start dates
- Planned completion dates
- Owners
- Dependencies
- Status
- Percent complete

## Step 3 - Define Dependencies

Milestones are sequenced so later activities depend on earlier work.

Example:

Site Survey
↓
Permitting
↓
Equipment Delivery
↓
Installation
↓
Acceptance

This helps show how one delay can affect later activities.

## Step 4 - Test Delay Scenarios

Six synthetic project scenarios are introduced.

Examples include:

- Permit delays
- Equipment delivery delays
- Crew availability conflicts
- Engineer scheduling conflicts

Each scenario identifies:

- Site
- Affected milestone
- Delay duration
- Resource conflict
- Proposed recovery action

## Step 5 - Evaluate Schedule Impact

For each scenario, the likely schedule impact is reviewed.

The goal is not only to identify the delay but also determine how work could be resequenced.

## Step 6 - Track Corrective Actions

An action log is maintained with:

- Action ID
- Site
- Action
- Owner
- Due date
- Status

This provides clear ownership and follow-up.

## Step 7 - Manage Schedule Changes

A formal example change request is included to demonstrate change control.

The change request documents:

- Requested change
- Reason
- Schedule impact
- Cost impact
- Decision status

## Step 8 - Report Project Status

The Excel workbook combines:

- Deployment schedule
- Delay scenarios
- Action log
- Change request

This creates a simple PMO reporting package for stakeholder review.
