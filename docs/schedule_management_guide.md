# Schedule Management Guide

## Purpose

This guide explains how the network deployment tracker can be used to manage planned work and project delays.

## Review the Schedule

Check each site's milestones for:

- Planned dates
- Owners
- Dependencies
- Current status
- Percent complete

## Review Dependencies

Confirm that prerequisite activities are completed before dependent work begins.

For example:

Installation should not begin before required equipment is delivered.

## Identify Schedule Risks

Examples include:

- Permit delays
- Late equipment
- Resource conflicts
- Engineer availability
- Acceptance delays

## Evaluate the Impact

For each issue, determine:

- Which milestone is affected?
- How many days may be lost?
- Which later milestones depend on it?
- Is another site or activity also affected?

## Consider Resequencing

Possible responses may include:

- Moving another activity forward
- Reassigning resources
- Changing crew sequencing
- Scheduling remote review
- Delaying dependent activities

## Document the Decision

Any significant schedule change should be captured in the change request log.

## Follow Up

Actions should remain open until:

- Ownership is confirmed
- Corrective action is completed
- Schedule is updated
- Stakeholders are informed
